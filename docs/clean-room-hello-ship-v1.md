# Clean-room `hello-ship` v1

This conformance package proves the public extension boundary from an isolated
temporary directory. The package is not copied from `Content Mod 2`, does not
load `Global Mod`, and contains no Runtime Lua. Its only declared public inputs
are:

- `schemas/cm2/source-envelope-v1.json`
- `tools/cm2-compiler/compile-definitions.ps1`
- `tools/cm2-sdk/cm2-sdk.ps1`
- `tools/cm2-preview/run-preview-suite-v1.ps1`

The fixture defines one player-controlled, single-body ship, one mount, one
ballistic weapon, one projectile and one impact effect. It owns a VOX marker,
texture, sound, localization resource and generated DTO. All package IDs are
under `cm2.cleanroom.hello-ship`, all package paths are relative, and the
manifest is data-only with a one-body/one-shape/zero-joint budget.

## Reproduction

Run the conformance runner and its assertions from the repository root:

```powershell
& .\tools\cm2-clean-room\run-clean-room-hello-ship-v1.ps1
& .\tools\cm2-clean-room\test-clean-room-hello-ship-v1.ps1
```

The runner creates `%TEMP%\cm2-clean-room-*\hello-ship`, hydrates hashes from
the actual isolated source files, and feeds the resulting manifest to the SDK
with `-FixturePath`. The shared Definition Compiler is run over a disposable
compiler staging directory containing the five source envelopes (vehicle,
mount, weapon, projectile and effect). The package then exercises SDK
`validate`, `build`, a second-root rebuild, `preview`, `test`, `package` and
`migrate`. An install/uninstall simulation copies only the published package
output and verifies that its generated directory is completely removed.

The runner also checks every source for private Core references, absolute or
traversal paths, and Lua entrypoints. Negative fixtures reject a missing
dependency and future package schema; a private-reference probe is rejected by
the same scanner. A before/after hash snapshot of `Content Mod 2` and `Global
Mod` must be identical (`coreDiff=0`).
